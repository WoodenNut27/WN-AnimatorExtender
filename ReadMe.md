VRChat アバター向けの Unity 拡張です。**同期パラメータの節約**と、**Animator 内での整数演算**を提供します。

| 機能 | できること |
|---|---|

| **CmpFloat Settings** | Float を指定した精度へ量子化して圧縮する |

| **Parameter Encoder / Decoder** | Bool ×8 と Int を相互変換する |

いずれもビルド時に自動処理され、アバターに WNAE のコンポーネントは残りません。

## 1. 動作環境とインストール

| 依存 | 動作確認バージョン | 要否 |
|---|---|---|
| Unity | 2022.3 | 必須 |
| VRChat SDK - Avatars | 3.10.4 | 必須 |
| NDMF (`nadena.dev.ndmf`) | 1.14.1 | 必須 |
| Modular Avatar | 1.17.1 | 任意（共存します） |

`WNAE_xxx.unitypackage` を Unity プロジェクトにインポートしてください。（xxxはバージョン）

Assets以下の `WoodenNut/WNAE` を削除することで Unity プロジェクトからアンインストールされます。

**Modular Avatar とは共存します。** MA のリネームとメニュー結合が終わった後の最終的な名前で処理されます。ただし **MA のリネーム先に `WNAE/` で始まる名前を指定しないでください**（内部で使う名前と衝突します）。

**Avatar Optimizer** は WNAE より後に実行されるため影響ありません。

## 2. WNAE CmpInt Settings

### 概要

VRChat の同期パラメータ予算は 256 bit で、`Int` は値域に関わらず一律 8 bit を消費します。衣装や髪型のスイッチは選択肢が数個しかないことが多く、大量のビットが無駄になっています。

**CmpInt** は、その Int をビルド時に必要最小限の同期 `Bool` へ自動分解します。値域 0〜5 なら 8 bit → 3 bit で **5 bit の節約**です。

Animator 上では**普通の Int のまま**なので、既存の遷移条件やアニメーションを変更する必要はありません。

### 使い方

アバター配下の任意の GameObject に **Add Component → WoodenNut → WNAE CmpInt Settings** を追加し、リストに圧縮したい Int を登録します。

1 つの GameObject につき 1 個までですが、複数の GameObject に分けて置いても全部まとめて処理されます（衣装プレハブごとに設定を持たせられます）。

`Name` は**アバターに登録済みの Int から選択**します（検索可）。VRCExpressionParameters と MA Parameters の両方が候補に出ます。新規パラメータの追加はできません。

### Options

`Name` 以外は Foldout に入っています。左端のチェックボックスが **OFF なら既存設定を継承、ON なら上書き**です。

| 項目 | 内容 |
|---|---|
| **Default** | OFF なら既存の `Default` を継承 |
| **Saved** | OFF なら既存の `Saved` を継承 |
| **Range** | OFF なら値域を自動検出。ON で `Min` / `Max` を手入力 |
| **Bool Prefix** | OFF なら生成 Bool 名は `{Name}_b0` … |

### 値域の自動検出

`Range` が OFF のとき、Animator とメニューを走査して値域を決めます。

**確実に検出できるもの** — 遷移条件の `Equals` / `NotEqual`、メニューの Toggle / Button の値、Parameter Driver の `Set` / `Random` / Convert Range 付き `Copy`、BlendTree の threshold。

**検出できないもの** — 遷移条件の `Greater` / `Less`、Parameter Driver の `Add` と Convert Range なしの `Copy`、**OSC からの書き込み**。

> **検出できないものがあると警告が出ます。** 値域を取り違えると、**範囲外の値は端にクランプされて同期され、ローカルとリモートで表示が食い違います。** 警告が出た場合や OSC で操作する場合は `Range` を ON にして手入力してください。

「再スキャン」ボタンで検出をやり直せます。Animator やメニューを別ウィンドウで編集した後に押してください。

### 圧縮率と生成されるもの

| 値の個数 | 必要ビット数 | 節約 |
|---|---|---|
| 1〜2 | 1 bit | 7 bit |
| 3〜4 | 2 bit | 6 bit |
| 5〜8 | 3 bit | 5 bit |
| 9〜16 | 4 bit | 4 bit |
| 17〜32 | 5 bit | 3 bit |
| 33〜64 | 6 bit | 2 bit |
| 65〜128 | 7 bit | 1 bit |
| 129〜256 | 8 bit | 節約なし |

元の Int は**必ず非同期**（0 bit）になり、生成された Bool が同期を担当します。FX に変換用レイヤーが 2 つ生成され、State 数は `値の個数 × 2 + 2` です。

リモート側は Bool が届いてから Int が復元されるため、切り替えに数フレームの遅延があります。

### エラーと警告

- **エラー** — 値が 1 つも検出できない / `Max` が `Min` 未満 / 値の個数が 256 超 / 名前が他のエントリと重複 / 生成 Bool 名が既存パラメータと衝突 / 対象パラメータが存在しない / 合計 256 bit 超過
- **警告** — 値域を確定できない書き込みがある / 値の個数が 64 超 / 8 bit で節約にならない

## 3. WNAE CmpFloat Settings

### 概要

VRChat の同期 Float は **-1〜1 を 8 bit で表す固定小数点**（256 段階）です。アニメーションのフレーム指定に使う場合、負の値は不要で 256 段階もの精度も要りません。

**CmpFloat** は、使う値域と精度を指定してその分だけの同期 `Bool` へ量子化します。0〜1 を 4 bit なら **4 bit の節約**です。

Float は連続値なので、CmpInt と違い**値域の自動検出は行いません**。

### 使い方

**Add Component → WoodenNut → WNAE CmpFloat Settings** を追加します。配置ルールと `Name` の選び方は CmpInt と同じで、CmpInt と同時に使えます。

### Options

| 項目 | 上書きトグル | 内容 |
|---|---|---|
| **Default** | あり | OFF なら既存の `Default` を継承 |
| **Saved** | あり | OFF なら既存の `Saved` を継承 |
| **Range** | **なし（常時有効）** | 圧縮する値域。既定は `0`〜`1` |
| **Bits** | **なし（常時有効）** | 圧縮後のビット数。既定は `4` |
| **Bool Prefix** | あり | OFF なら `{Name}_b0` … |

- `Range` は **-1〜1 の範囲**で指定します。範囲外や `Min >= Max` はエラーです
- `Bits` は **2〜7** です。1 bit は Bool と同じ、8 bit は無圧縮と同じなので範囲外はエラーです

### 量子化

段階数は `2^Bits` で、両端を含みます。

```
間隔  = (Max - Min) / (2^Bits - 1)
値(k) = Min + k × 間隔
```

| Bits | 段階数 | 分解能（0〜1 の場合） | 節約 | 生成 State 数 |
|---|---|---|---|---|
| 2 | 4 | 0.3333 | 6 bit | 10 |
| 3 | 8 | 0.1429 | 5 bit | 18 |
| 4 | 16 | 0.0667 | 4 bit | 34 |
| 5 | 32 | 0.0323 | 3 bit | 66 |
| 6 | 64 | 0.0159 | 2 bit | 130 |
| 7 | 128 | 0.0079 | 1 bit | 258 |

`Bits` が 6 以上だと警告が出ます。

### ローカルとリモートの差

**ローカル側の Float は量子化されません。** 連続値のまま使われ、リモート側だけが `2^Bits` 段階になります。

これは VRChat の標準挙動と同じ性質です。素の同期 Float もローカルは高精度、リモートは 8 bit です。CmpFloat はリモートの粒度を 256 段階から `2^Bits` 段階へ落としているだけです。

値域外の入力は端の段階にクランプされます。

## 4. WNAE Parameter Calculation

### 概要

VRChat の Parameter Driver は `Add` が**定数加算しかできず**、パラメータ同士の演算を行う公式手段がありません。

**WNAE Parameter Calculation** は State に Add Behaviour するだけで `c = a op b` を宣言できます。ビルド時にその State は Sub State Machine へ置き換えられ、Parameter Driver と遷移条件の組み合わせに展開されます。

### 使い方

Animator の State を選択し、**Add Behaviour → WNAE Parameter Calculation** を追加します。FX 以外のレイヤーでも構いません。

> **この State は演算専用になります。** State ごと置き換えられるため、**Motion や他の Behaviour を設定しても失われます**（警告が出ます）。アニメーションは別の State に用意してください。

| 項目 | 内容 |
|---|---|
| **Operation** | 演算種別（14 種） |
| **A / B (入力)** | `NOT` では B を使いません |
| **C (出力)** | A や B と同じパラメータを指定できます |
| **Bit Width** | 演算のビット幅（1〜8、既定 8） |

A / B / C は**開いている Animator ウィンドウの Int パラメータ**から選択します。取得できない場合は手入力になります。一覧が古いときは「パラメータ一覧を再取得」を押してください。

**A・B・C に同じパラメータを指定できます。** 先に中間パラメータへ退避してから計算するので `a = a + a` のような書き方でも壊れません。

### 演算種別

ビット幅を N、`mod = 2^N` とします。

| 演算 | 内容 |
|---|---|
| **Add** | `c = a + b`。和が `mod` 以上なら `c % mod` |
| **Sub** | `c = a - b`。差が負なら `c + mod` |
| **Mul** | `c = a * b`。積が `mod` 以上なら `c % mod` |
| **Div** | `c = a / b`（切り捨て） |
| **Mod** | `c = a % b` |
| **NOT** | `c = ~a`（N ビット幅で反転）。b は無視 |
| **AND** | `c = a & b` |
| **OR** | `c = a \| b` |
| **XOR** | `c = a ^ b` |
| **XNOR** | `c = ~(a ^ b)`（N ビット幅） |
| **L-SHIFT** | `c = (a << b) & (mod - 1)`。`b >= N` は `c = 0` |
| **R-SHIFT** | `c = a >> b`。`b >= N` は `c = 0` |
| **L-ROTATE** | `c = a` を左に `b` ビット回転。押し出されたビットは右端へ回り込む |
| **R-ROTATE** | `c = a` を右に `b` ビット回転。押し出されたビットは左端へ回り込む |

- **ゼロ除算** — `Div` / `Mod` ともに `b = 0` なら `c = 0`
- **回転量** — `b` は `b mod N` として扱われます（N=8 なら `b=8` は無回転）。シフトと違い `b >= N` でも 0 になりません
- **剰余は 256 ではなく `2^BitWidth`** です。Bit Width 4 なら `% 16` です

```
N = 8, a = 142 (1000 1110), b = 1
L-ROTATE →  29 (0001 1101)
R-ROTATE →  71 (0100 0111)
```

### Bit Width の決め方

**Bit Width は生成 State 数を大きく左右します。** 実際に使う値域に合わせて絞ってください。Inspector に生成 State 数が表示されます。

| 演算 | N=4 | N=6 | N=8 |
|---|---|---|---|
| Add / Sub | 8 | 10 | 12 |
| NOT | 6 | 8 | 10 |
| AND / OR / XOR / XNOR | 18 | 26 | 34 |
| L-SHIFT | 10 | 14 | 18 |
| R-SHIFT | 17 | 30 | 47 |
| L-ROTATE / R-ROTATE | 25 | 49 | 80 |
| Mul | 20 | 33 | 54 |
| **Div / Mod** | **44** | **186** | **760** |

512 State を超える設定では警告が出ます。

### 実行にかかるフレーム数

Parameter Driver は **State 進入時にしか実行されない**ため、演算は 1 フレームでは完結しません。以下は最悪値です（括弧内は平均）。

| 演算 | N=4 | N=6 | N=8 |
|---|---|---|---|
| NOT / AND / OR / XOR / XNOR | 6 | 8 | 10 |
| L-SHIFT | 6 (3.2) | 8 (3.1) | 10 (3.1) |
| Add / Sub | 7 (5.0) | 9 (6.0) | 11 (7.0) |
| R-SHIFT | 7 (3.3) | 9 (3.2) | 11 (3.1) |
| Div / Mod | 7 (3.6) | 9 (3.7) | 11 (3.7) |
| L-ROTATE / R-ROTATE | 9 (6.0) | 12 (7.5) | 16 (9.5) |
| Mul | 12 (7.5) | 17 (10.1) | 21 (12.6) |

- 元の State から出ていく遷移は**演算が終わってから**評価されます
- **State に入った直後に c を読む使い方はできません**

### 注意

**演算結果 `c` に同期パラメータを指定した場合の挙動は未検証です。**

展開されたチェーンはローカル・リモートの両方で実行されます。`c` が同期パラメータだと、所有者の値がネットワーク同期される一方でリモートも自分で計算するため、**計算中の数フレームだけ食い違う可能性があります**。

確実を期すなら `c` には非同期パラメータを指定し、同期が必要なら CmpInt で圧縮して同期させてください。

なお **CmpInt の値域自動検出は演算結果を追えません。** `c` を CmpInt にする場合は `Range` の手入力が必要です。

中間パラメータ（`WNAE/Calc/...`）が Animator に追加されますが、VRCExpressionParameters には追加されないので同期予算は消費しません。

## 5. WNAE Parameter Encoder / Decoder

### 概要

**8 個の Bool** と **1 個の Int** を相互変換します。

| Behaviour | 向き |
|---|---|
| **Parameter Encoder** | Bool ×8 → Int |
| **Parameter Decoder** | Int → Bool ×8 |

Parameter Calculation と同じく、State に Add Behaviour するとその State が置き換えられます。**Motion や他の Behaviour は失われます。**

**Parameter Calculation と同じ State に混ぜられます。** リスト順に直列実行されるので「Int を分解 → ビットごとに演算 → Int に戻す」を 1 つの State にまとめられます。

### ビットの並び

**`Bit 1` が LSB（`2^0`）、`Bit 8` が MSB（`2^7`）** です。

| Bit 8 | Bit 7 | Bit 6 | Bit 5 | Bit 4 | Bit 3 | Bit 2 | Bit 1 |
|---|---|---|---|---|---|---|---|
| 128 | 64 | 32 | 16 | 8 | 4 | 2 | 1 |

### Encoder

**出力 (Int)** と、**Bit 1 〜 Bit 8** それぞれの入力元を指定します。

各ビットは **`0 固定` / `1 固定` / Bool パラメータ** から選べます。既定は `0 固定` です。固定値は分岐を作らないので、**使うビットが少ないほど生成 State 数が減ります**。

生成 State 数は `パラメータ指定のビット数 × 2 + 2`（8 ビットすべて指定で 18）。完了まで `ビット数 + 2` フレームかかります。

### Decoder

**入力 (Int)** と、**Bit 1 〜 Bit 8** それぞれの出力先 Bool を指定します。**`（非選択）` にするとそのビットは出力されません。**

生成 State 数は `(8 - 最下位の選択ビット) + 2` です。上位ビットだけ使えば短く済みます（Bit 5 以上のみなら 6、Bit 1 まで使うと 10）。完了まで `立っているビット数 + 2` フレームです。

選択した出力は開始時に一度すべて `false` になり、立っているビットだけが後から `true` になります。**完了までの数フレームは過渡状態です。**

同じ Bool を複数のビットに割り当てると警告が出ます（どちらかが立っていれば `true` になります）。

## 6. 既知の制限・未検証事項

以下は β1 時点のものです。

- **実機（VRChat 上）での動作確認が未了です。** Unity エディタ上での生成結果と、`Tests/` のマネージド遷移モデルによる検証（198,258 assertions）までは確認済みですが、アップロードして複数人で同期させた状態での検証は行っていません
- **演算の網羅検証は Bit Width 1〜4 が全入力、5〜8 は境界サンプルです。** 全ビット幅の全入力を突き合わせているわけではありません（`Tests/WNAEModelTests.cs`）
- **β1 の修正は、Unity / SDK / NDMF の参照を使ったコンパイルと、実ソースの生成処理を動かすマネージド遷移モデルで検証しています。** Float の中点と隣接値、AnyState の条件保持・割り込み・再進入、名前衝突、大きな Range などを検査していますが、今回の変更後の Unity ネイティブ遷移評価と実際の MA ビルドを含む統合テストは未了です
- **`Copy` の Convert Range の実装詳細（クランプの有無・Int への丸め規則）が VRChat SDK のソースから確認できません。** そのため、変換元範囲を 2 の冪（`0〜2^N`）にして入力が必ず範囲内に収まるようにし、結果が浮動小数点でも厳密な整数になる定数倍（`Mul` / `L-SHIFT`）に限定しています。この構成ではクランプ・丸めのどちらの仕様でも結果が変わらないはずですが、実機未確認である点は変わりません
- **CmpInt の値域自動検出は、OSC や Parameter Calculation の演算結果を追えません。** 該当する場合は `Range` の手入力が必要です
- **極端に大きな Int の値域は正しく圧縮できません。** Animator の遷移条件と Parameter Driver の値は float で保持されるため、`2^24`（16,777,216）を超える整数は 1 つずつ区別できません。値の個数が 256 以下でも、`Range` に `16777216`〜`16777217` のような値域を手入力すると、エンコード・復元のどちらも失敗します。現在この検査は行っていないので、大きな値を使う場合は値域を `2^24` 未満に収めてください
- **Modular Avatar のリネーム先を WNAE の中間パラメータ名と同じにするとビルドが失敗します。** `WNAE/Calc/{連番}/acc` のような名前へ MA でリネームすると、パラメータ名が重複して MA 側で例外が発生します。`WNAE/` で始まる名前を MA のリネーム先に指定しないでください
- **アセットが壊れている場合、演算種別が別のものとして実行されることがあります。** `Operation` やビットの入力元に未知の値が保存されていると、エラーにならず Div（除算）や `0 固定` として扱われます。YAML を手編集した場合や、新しい版で保存したアセットを古い版で開いた場合に起こり得ます
- **実行時に Float パラメータへ NaN が書き込まれると、その CmpFloat の同期が止まります。** すべての遷移条件が成立しなくなるため、生成 Bool が直前の値のまま固定されます。有限値が書き込まれれば復帰します。OSC など外部からの入力で NaN を送らないでください
- Div / Mod は Bit Width 8 で 1 個あたり約 760 State を生成します。多用する場合は Bit Width を絞ってください

## 7. 更新履歴

### β1（2026/09/13）

α2 公開後に見つかった不具合をまとめて修正した版です。

**修正**

- **CmpInt の値域外の入力で同期が止まる問題を修正。** 値域を外れた値は端へクランプされるようになりました（CmpFloat と同じ扱い）。従来は生成 Bool が直前の値のまま固まり、リモートとの不一致が解消されませんでした
- **CmpFloat で入力が一定でも生成 Bool が隣の段階と交互に切り替わる問題を修正。** 中点の扱いを低い段階へ統一しました
- **AnyState の条件が ON のままだと、展開した Behaviour が再進入を繰り返して完了しない問題を修正**
- **エラーがあってもビルドが成功してしまう問題を修正。** エラーは NDMF のエラーレポートに登録され、**アップロードがブロックされます**。同期パラメータが 256 bit を超えた場合などに、設定が無言で無視されたまま公開されることはなくなりました
- **Modular Avatar のリネームに追従しない問題を修正。** Behaviour を MA より前に展開するようにし、リネーム先を後から変更した場合はエラーを出します。従来は古い名前のパラメータを新規作成し、本来の対象が無圧縮のまま残っていました
- **生成 Bool 名の衝突検査を修正。** 既存の Expression / Animator パラメータ、他エントリの本体名とも突き合わせます
- **Calculation / Encoder / Decoder のパラメータ型の不一致をエラーにしました。** 従来は警告のみで展開を続けていたため、Bool に 0〜255 を書くなど結果が無言で変質する可能性がありました
- **CmpInt の値域自動検出に、メニューの OFF / 解除時の `0` を追加**
- **大きな Int の値域でのオーバーフロー・無限ループを修正。** Float の非有限値と、区別できない量子化段階も検証するようにしました

**変更**

- **エラー時の挙動が変わりました。** 従来は該当項目だけを飛ばしてビルドを続行していましたが、β1 からはアップロードを止めます

**文書**

### α2（2026/08/15）

**追加**

- **WNAE Parameter Encoder / Decoder** を追加（Bool ×8 ⇔ Int の相互変換）
- Parameter Calculation に **L-ROTATE / R-ROTATE** を追加
- 1 つの State に**種類の違う Behaviour を混在**させて直列実行できるようになりました

**変更**

- Parameter Calculation から **`Copy`（`c = a`。b は無視）を削除**しました
- 生成される Sub State Machine の構造を見直し、**State 数と所要フレーム数を削減**しました（Bit Width 8 の場合：Div / Mod 1262 → 760、Mul 275 → 54、R-SHIFT 83 → 47、L/R-ROTATE 139 → 80、Add / Sub 21 → 12、Decoder 17 → 10）

**修正**

- 置き換え元の State が Default State だったとき、追加される Entry 遷移が既存の条件付き Entry 遷移を遮っていた問題
- 置き換え元の State に Exit へ抜ける遷移があったとき、「親のステートマシンから抜ける」という意味が失われていた問題
- `Mul` / `L-SHIFT` が使う Convert Range の変換元範囲を `0〜1` から `0〜2^N` に変更（クランプの有無や丸め規則に結果が依存しないようにするため）

> **α1 から更新する場合の注意**
> `Operation` は列挙値の順番で保存されます。α1 の `Copy` は列挙値の 12 番目で、α2 以降は同じ位置が **`L-ROTATE`** です。そのため **α1 で `Copy` を選択していた Behaviour は、α2 以降では `L-ROTATE` として読み込まれます。**
>
> α1 の `Copy` は B を使わなかったため、多くの場合 B は未設定のはずです。その場合は「Parameter B が指定されていません」というエラーになり、その Behaviour は展開されません（ビルドログで気づけます）。
>
> ただし **B に値が残っていた場合はエラーになりません。`c = a` のつもりが `c = a を b ビット左回転` として動きます。** α1 から更新する場合は、`Copy` を使っていた Behaviour が無いか確認してください。`Copy` は削除されたので、同じ動作は公式 Parameter Driver の `Copy` に置き換えてください。
>
> α2 から更新する場合、列挙値の変更はありません。
